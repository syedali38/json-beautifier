What Is JSON to YAML Conversion?

          

            This converter reads the editor with JSON.parse, then writes YAML from the
            parsed JavaScript value. The YAML is a new document, not a restyle of the
            JSON source. Duplicate keys, integer-like key order, and JavaScript numbers
            are already decided before any YAML is produced.
          

          

            The writer uses the YAML core schema and YAML 1.1-compatible quoting.
            Strings such as yes, no, on, off, and 01 are quoted so tools that still
            treat those words as booleans are less likely to change the type.
            That quoting is practical help. It is not complete YAML 1.1 compatibility,
            and it is not a claim that every YAML 1.1 program will accept the file.
          

          

            The reverse direction is the
            YAML to JSON converter,
            which reads YAML 1.2. There an unquoted yes stays a string. Here the same
            word is written in quotes. Parsing, conversion, copy, and download all run
            in this browser. The JSON is not uploaded.
          

        


        

          
How to Convert JSON to YAML

          

            

              
Step 1: Add JSON

              

                Paste JSON into the editor, choose Open JSON File, or choose Load Sample JSON.
                Open JSON File converts as soon as a valid file is read.
                Load Sample JSON converts immediately.
              

            

            

              
Step 2: Convert pasted JSON

              

                Pasted JSON needs Convert to YAML. Invalid JSON stays in the editor.
                The status line includes the parser message, and the YAML preview is cleared.
              

            

            

              
Step 3: Read the YAML

              

                The preview shows YAML from the last successful convert.
                Editing the JSON does not clear that preview, so the YAML can be out of date
                until you convert, copy, or download again.
              

            

            

              
Step 4: Copy, download, or clear

              

                Copy YAML converts the current editor text, then copies that YAML.
                Download YAML converts the current editor text and saves converted-data.yaml.
                Neither button copies a stale preview. Clear empties both panels.
              

            

          

        


        

          
How This Converter Writes YAML

          

            After JSON.parse succeeds, the page stringifies the value with the YAML core
            schema, YAML 1.1-compatible quoting, an 80-character line width, and no
            generated YAML anchors for duplicate objects.
          

          
YAML core schema

          

            Booleans, null, and numbers are written as core-schema scalars.
            Strings that would be ambiguous as another type are quoted.
            Unicode such as 東京 stays as characters, not JSON \u escapes.
          

          
YAML 1.1-compatible quoting

          

            Values and some keys that YAML 1.1 could read as booleans or numbers are quoted.
            That includes yes, no, on, off, true as a string, 01, 1.0 as a string, and
            keys such as y and n. The examples below show the quotes this writer emits.
            Do not treat the file as certified YAML 1.1.
          

          
Line width 80

          

            A long string that contains spaces may continue on the next YAML line with
            extra indent, near an 80-character width. A long unbroken string may stay on
            one line. Either way, the YAML keeps the original string value.
          

          
No generated YAML anchors

          

            Nested objects that look the same are written out in full.
            This converter does not emit YAML anchors or aliases (& / *) for duplicate
            objects. JSON.parse also creates a separate object for each nested object in
            the JSON, so the input path never shares one object across two keys.
          

          
Download filename

          

            Download YAML saves converted-data.yaml. JSON to YML uses the same YAML text.
            Both .yaml and .yml are common filename extensions. This download uses .yaml.

What JSON.parse Changes Before YAML Is Written

          

            JSON.parse runs first. The YAML shows the JavaScript value that parse produced,
            not every character of the JSON source. The
            JSON Beautifier
            documents the same parse behavior when the result is formatted JSON instead of YAML.
          

          
Duplicate keys

          

            If a key is repeated, JSON.parse keeps the last value. The YAML then contains
            only that value.
          

          
Input

          
{"role":"reader","role":"admin"}

          
Output

          
role: admin


          
Integer-like object keys

          

            Keys that look like array indexes are ordered numerically, then the remaining
            keys. The names are not renamed. This YAML writer also quotes those keys.
          

          
Input

          
{"10":"ten","2":"two","name":"Ada","1":"one"}

          
Output

          
"1": one
"2": two
"10": ten
name: Ada


          
1.0 becomes 1

          

            JSON.parse uses JavaScript numbers. A trailing .0 is not kept.
            The YAML shows the number JavaScript kept.
          

          
Input

          
1.0

          
Output

          
1


          
Input

          
{"value":1.0}

          
Output

          
value: 1


          
Large integer precision

          

            Integers outside ±9007199254740991 can change. 9007199254740993 is not
            preserved.
          

          
Input

          
9007199254740993

          
Output

          
9007199254740992


          
Negative zero

          

            JSON.parse can keep a JavaScript negative zero. This YAML writer prints that
            value as -0. It does not rewrite it as 0.
          

          
Input

          
{"value":-0}

          
Output

          
value: -0


        


        

          
Common Conversion Errors

          
Invalid JSON

          

            Trailing commas, comments, and single quotes are rejected.
            The status line starts with Invalid JSON: and then includes the parser message.
            The converter does not rewrite the JSON, and the YAML preview is cleared.
          

          
Unquoted property names

          

            JSON object keys must be double-quoted. Text such as {name:"Ada"} is rejected
            as invalid JSON. The editor is left as it was.
          

          
Extra JSON values

          

            JSON.parse accepts one value. Text after a complete value, such as {"a":1} true
            or true false, is rejected. The status line includes the parser message.
          

          
Empty or whitespace-only input

          

            An empty editor, or an editor that contains only whitespace, shows
            Paste JSON or open a .json file first.
            An empty uploaded file is rejected before conversion.
            A file that contains only whitespace is also rejected, with a separate status line.
          

          
File too large

          

            A JSON file larger than 5 MiB is rejected before it is read.
            Pasted JSON is not checked against that limit.
            Very large pasted text can still be limited by the browser's memory and performance.
          

          
Conversion failure

          

            If the JSON parses but cannot be written as YAML, the status line is
            The JSON could not be converted to YAML.
            The preview is cleared. Copy YAML and Download YAML stop without copying or saving.
          

        


        

          
Frequently Asked Questions

          
Why is the old YAML preview still visible after I edit the JSON?

          

            This page does not clear the YAML when the JSON editor changes.
            Convert to YAML updates the preview from the current editor.
            Copy YAML and Download YAML also convert the current editor first.
            Clear empties both panels.
          

          
Does Copy YAML copy the preview or convert the current input?

          

            Copy YAML converts the current JSON, then copies that YAML.
            It does not copy a stale preview.
            Download YAML converts the current JSON, then saves converted-data.yaml.
            If conversion fails, nothing is copied or downloaded.
          

          
Why are some YAML strings quoted?

          

            A plain yes, no, on, off, true, or number-like string can be read as another
            type by YAML 1.1 tools. Quotes keep the original text a string.
            That is YAML 1.1-compatible quoting, not a guarantee that every YAML 1.1
            program will accept the file.
          

          
Can JSON arrays or primitive values be converted?

          

            Yes. A JSON array, string, number, boolean, or null is converted.
            The root value does not have to be an object.
          

          
Where can I inspect the JSON first?

          

            Use the JSON Viewer to open the tree, the
            JSON Beautifier to format the text, or the
            JSON to CSV converter when you need a table.
            Use JSON Escape and Unescape when you need to escape or unescape a JSON string rather than convert JSON into YAML.
            Use the YAML to JSON converter when you already have YAML and need JSON.
